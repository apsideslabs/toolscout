    Method

    How an entry gets here

    Four rules, no exceptions

    • Every entry earns its place by solving a specific problem a developer has. A tool can sit under several jobs — Postgres is both a database and a search option.

    • Where a project lives on GitHub, its last push, licence, language and stars are read from the GitHub API at build time. “Updated” is the last push to the default branch.

    • Fresh is a push within 30 days, slowing within a year, stale beyond that. Archived means the maintainer closed the repository. Only fresh is a green light.

    • Nothing here is ranked by who paid. Order is by your query, by recency, or by stars — and a listing still never proves a tool is safe or maintained.

    Before you install anything

    1. Read the last commit and the last release. Commits this month plus a release this quarter is alive. An eighteen-month-old release is a risk you are choosing to take.
    2. Treat stars as an order of magnitude. 40,000 against 400 is real information. 12,000 against 9,000 is noise.
    3. Check the licence, and any recent change to it. A move from an open licence to source-available is a commercial pivot, and the free tier becomes a business decision.
    4. Look for a Docker image and a Compose file. They signal that upgrades, persistent data and reverse proxies have been thought about.
    5. Read the open issues, not the README. Sort by most-commented. It shows what actually hurts, and whether maintainers answer.
